SLIDE 2 - PROJECT CONTEXT
============================================================

Indonesian mastery:
Inti slide ini: masalahnya bukan siswa belum bisa coding AI. Masalahnya siswa bisa terlalu percaya pada output AI. Literasi AI berarti siswa paham AI itu prediktif, bisa salah, dan perlu dievaluasi.

English script:
This project starts from a simple but important problem. AI is now present in many daily activities, including learning tools, search engines, recommendation systems, and digital applications. However, many students may still treat AI output as a final answer.

The first problem is that AI output is often accepted without evaluation. If students only see the final result, they may think that AI is always correct. The second problem is that AI concepts are abstract, especially for junior high school students. Terms like prediction, confidence, and error are difficult to understand if they are only explained theoretically.

Because of that, this proposal uses an interactive direction. Instead of only explaining AI, the system lets students experience AI prediction directly. Students draw something, see the AI prediction, compare the result, and decide whether the prediction should be accepted or corrected.

The project is also inspired by exploratory AI literacy approaches for younger learners, but the implementation here is visual classification and gameplay decision-making.

What I want to emphasize here is that the project is not trying to teach students how to build an AI model. The goal is more fundamental: helping students understand that AI output is uncertain and must be evaluated.

SLIDE 3 - PROPOSED SOLUTION
============================================================

Indonesian mastery:
Slide ini alur besar sistem. Hafalkan loop: Draw, Predict, Top-3 UI, Decide, Consequence, Log. Kalau dosen tanya kontribusi utama, jawab: membuat output AI jadi pengalaman interaktif yang bisa divalidasi siswa.

English script:
The proposed solution is a web-based interactive simulation. The learning flow is built around six steps.

First, the student draws an object through a canvas-based interaction. Second, the drawing is processed as input for AI prediction. Third, the system displays the result through a Top-3 UI, so the student does not only see one final answer. Fourth, the student makes a decision: accept, correct, override, or redraw. Fifth, the selected decision affects the behavior of the object inside the 2D gameplay. Finally, the interaction is recorded as a log.

This flow is important because the AI prediction is not the end of the process. The prediction becomes a checkpoint. The student must evaluate the output before it is used in the game.

The MediaPipe hand tracking component supports this interaction by making the input more direct. Students can draw using finger movement, so the experience feels more active than simply selecting answers from a quiz.

SLIDE 4 - SYSTEM DESIGN OVERVIEW
============================================================

Indonesian mastery:
Jangan jelaskan semua kotak terlalu detail. Jelaskan tiga bagian: input, process, output. Poin penting: ada decision resolver sebagai lapisan HITL, jadi AI tidak langsung menentukan gameplay.

English script:
This slide shows the global system design. The system can be understood through three major parts: input, process, and output.

The input part includes the camera stream, finger tracking interaction, canvas drawing, and student decision. These inputs are important because the system does not only receive a drawing, but also receives the student's judgment after the AI prediction appears.

The process part includes several layers. The interaction layer handles the drawing and gameplay environment. The AI classification layer produces prediction results. Then, the Human-in-the-Loop layer works as a decision resolver. This is where the student's decision is used to determine the final label of the object.

The output part includes the Top-3 prediction interface, the gameplay outcome, the learning feedback, and the interaction data. So the output is not only visual gameplay; it also includes data that can be reviewed later.

The key point is that the AI result is not directly executed. It must pass through a human decision first. This is the main design principle of the system.

The interaction matrix is used to map the relationship between user input, system response, and the context where the interaction appears.

For example, the first interaction is presence detection. When the student waves a hand, the system starts and the visual companion can greet the student. Then, the navigation interaction allows the student to move through the menu and tutorial.

The most important interaction is the AI decision. At this point, the student chooses accept, correct, override, or redraw. This decision determines the final label before the object is used in gameplay.

Other interactions, such as movement, feedback, recovery, and reflection, support the complete learning loop. This matrix helps ensure that every student action has a clear system response.

============================================================
SLIDE 7 - TOP-3 UI AND HUMAN DECISION
============================================================

Indonesian mastery:
Ini slide inti. Pakai kalimat kuat: "AI gives suggestions, but the student makes the final decision." Confidence tinggi bukan berarti pasti benar. Top-3 UI membuat siswa membandingkan output.

English script:
This slide shows the main Human-in-the-Loop checkpoint in the system.

After the drawing is submitted, the AI shows the Top-3 prediction with confidence score. The system does not immediately use the first prediction as the final answer. Instead, the student must make a decision.

There are four decision options. Accept means the student trusts the first prediction. Correct means the student chooses another prediction from the Top-3 list. Override means the student rejects all AI suggestions and inputs a different label. Redraw means the student decides that the drawing is unclear and returns to the canvas.

This design supports AI literacy because students learn that AI output is not absolute. Even when AI gives a confident prediction, the student still has to evaluate whether it matches the drawing intention.

The simple principle is: AI gives suggestions, but the student makes the final decision.

Transition:
After the final decision is made, the system needs to translate that decision into gameplay behavior.

============================================================
SLIDE 8 - OBJECT BEHAVIOR MAPPING
============================================================

Indonesian mastery:
Slide ini menjelaskan kenapa keputusan siswa punya konsekuensi. Kalau label benar dan aman, objek membantu. Kalau salah/berbahaya, objek bisa jadi danger atau fail. Ini membuat literasi AI terasa konkret.

English script:
After the student makes a decision, the final object label is mapped into gameplay behavior.

There are three main categories. A safe support object becomes a solid object. It can help the student progress, for example as a ladder, bridge, or stairs. A harmful object becomes a danger object. It can cause a fail condition or block progress, for example fire or lightning. If the object is invalid or unclear, the system can guide the student to redraw or correct it.

This mapping is important because the decision does not stop at the interface. The decision has a visible consequence inside the game world.

For students, this makes the AI validation process more concrete. They can see that accepting, correcting, or rejecting a prediction can change what happens in the level.

Transition:
To make this learning process gradual, the system uses level-based interaction design.

============================================================
SLIDE 9 - LEVEL INTERACTION DESIGN
============================================================

Indonesian mastery:
Tiga level bukan konten game random. Level 1 pengenalan, Level 2 ambiguitas, Level 3 validasi kritis. Ini progres pembelajaran AI literacy dari mudah ke kritis.

English script:
The level design is structured to gradually increase the complexity of AI uncertainty.

Level 1 is guided recognition. The student draws a simple object, and the system mainly shows a Top-1 prediction. The goal is to introduce the basic loop: draw, predict, accept, and see the object in the game.

Level 2 introduces ambiguity. The system displays Top-3 prediction and confidence score. At this stage, the student needs to compare alternatives and decide whether the first prediction is really the best answer.

Level 3 introduces a more critical decision. The AI may produce a confident but wrong prediction. This level asks the student to override or redraw when necessary. The learning point is that high confidence does not always mean correct.

So the level progression is not only about game difficulty. It is about increasing the student's responsibility in evaluating AI output.

The student flow is divided into three main phases: create, decide, and consequence.

The use case diagram also shows that the system has different roles. The student uses the simulation, draws objects, views predictions, makes decisions, and plays the level. The admin can review session data and interaction data. The super admin manages higher-level system access and configuration.

However, the main focus of this proposal remains the student experience: how the student interacts with AI output and how that interaction becomes part of learning.

English script:
This slide explains the system hierarchy behind the user experience.

The first layer is interaction. At this layer, the system must feel natural and easy to enter. Students should be able to start from simple actions such as camera-based gesture, drawing on the canvas, and following a clear interface. If the interaction feels difficult, students may stop before reaching the educational part.

The second layer is gameplay and storyline. The simulation uses a simple puzzle-platformer context so that the student's drawing and decision have a goal. The student is not only answering a question; the student is trying to make progress inside the level.

The third layer is education. This layer appears after the student experiences the interaction and gameplay consequence. In other words, the learning point is delivered through reflection, not through a long lecture.

The mascot works as the bridge between these three layers. It softens instruction, signals uncertainty, gives short warnings, and helps connect gameplay feedback to AI literacy. The mascot represents AI as an assistant, but it does not replace the student's decision. This supports the design principle: teach without making students feel lectured.

MIT Little Language Models / CoCo is used only as conceptual design inspiration, not as a technical reference. This project does not build a language model. What is adapted is the idea that AI literacy for younger learners should be exploratory, concrete, and playful. In this project, that idea is applied through sketch-based visual classification, Top-3 prediction, confidence score, Human-in-the-Loop decisions, and gameplay consequences.

English answer:
The novelty is not in creating a new AI model, but in integrating sketch-based interaction, Top-3 prediction, Human-in-the-Loop decision making, and gameplay consequence into one AI literacy learning experience.

If asked: "Why junior high school students?"
Indonesian:
Karena siswa SMP sudah mulai berinteraksi dengan AI, tapi kemampuan evaluasi output masih berkembang. Sistem dibuat konkret dan berbasis game agar konsep prediksi dan confidence lebih mudah dipahami.
English answer:
Junior high school students already interact with AI systems, but their ability to evaluate AI output is still developing. This system uses concrete and game-based interaction to make prediction, confidence, and error easier to understand.

If asked: "Why Top-3 instead of only Top-1?"
Indonesian:
Top-1 membuat AI terlihat seperti jawaban final. Top-3 menunjukkan ada alternatif dan tingkat keyakinan, sehingga siswa terdorong membandingkan.
English answer:
Top-1 can make AI look like a final answer. Top-3 shows alternatives and confidence levels, so students are encouraged to compare and evaluate the prediction.

If asked: "What is Human-in-the-Loop in this project?"
Indonesian:
HITL terjadi ketika siswa melihat prediksi AI lalu menentukan keputusan akhir: accept, correct, override, atau redraw. Jadi manusia bukan penonton, tapi validator.
English answer:
Human-in-the-Loop happens when the student sees the AI prediction and determines the final decision through accept, correct, override, or redraw. The student is not only an observer, but a validator.

My scope focuses on frontend interaction, UI/UX, Top-3 UI, gameplay flow, feedback, wireframe, interaction matrix, and level interaction design.

English answer:
The mascot is used as a visual feedback element and a bridge between interaction, gameplay, and education. It helps students understand system states without long instructions. It is not a chatbot and not the main AI model.

If asked: "Why put education at the last layer?"
