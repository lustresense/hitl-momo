## 0. Perintah eksekusi dan batas kritis

1. **GPU server digunakan untuk seluruh pekerjaan training yang berat**, termasuk image/temporal teacher, self-supervision/pseudo-label terkontrol, distillation, retraining student gesture, augmentasi low-light, sweep, kalibrasi dan evaluasi. Model teacher dan dataset **tidak pernah dikirim ke laptop siswa**. Student kecil bisa dilatih GPU jika backend memadai, tetapi latency inference tetap diuji pada CPU sungguhan.
2. **Runtime pengguna: semua model vision/NUI inference harus `CPU`**, termasuk MediaPipe HandLandmarker serta face model bila dipanggil di NUI Lab. Classifier R20 menggunakan JS/CPU atau WASM/CPU. Jangan menciptakan dependency GPU delegate atau WebGL inference. **Akselerasi browser untuk menggambar UI biasa tidak identik dengan GPU inference** dan tidak perlu dilarang.
3. **Total transfer pertama pengguna harus di bawah 25.000.000 byte** (25 MB desimal, bukan sekadar bobot classifier). Ukur jaringan dari browser profil bersih, tanpa cache, untuk *journey* yang ditentukan. Model R20 raw <= **200.000 byte** adalah budget kandidat, bukan jaminan kelayakan keseluruhan.
4. Tetap pakai **R19 G4 Hybrid + FSM** sebagai pembanding beku. R20 boleh mengubah classifier, aturan geometri/calibration, preprocessing, atau scheduling sebagai **candidate terpisah dengan ablation**, tetapi **jangan mengubah semua faktor sekaligus**.
5. Uji **malam 19 November** membutuhkan hardware dan webcam Owner. Tidak boleh mengubah `PHYSICAL_WEBCAM` menjadi PASS dari hasil dataset/simulated/headless. Bila model belum benar-benar terpasang di lab Owner, catat blocker, jangan klaim siap test.
6. Tidak mengakses `main:contexts/can/research/.context-notforagent/`; jangan menaruh rekaman pengguna, wajah, raw dataset, secrets, atau output berukuran besar di repo publik.
7. Ikuti root `research-can/AGENTS.md`, `README.md`, `LOG.md`. `research-can` orphan, **jangan di-merge**. Commit riset harus mengubah `LOG.md` dan `README.md` dalam commit yang sama. Jangan push/deploy `main` tanpa otorisasi terpisah.

**Aturan keras saat mempromosikan `EVAL_ONLY -> TRAIN`:** setiap sumber/sampel yang digunakan untuk training R20 tidak lagi sah sebagai **independent test R20**. Catat provenance per `source_id / person_id / session_id / clip_id / frame_idx / lighting / handedness / labeler / license / sha256`. Taruh sample yang tetap OOD pada subject atau sesi disjoint yang benar. Jangan mengklaim R19 old OOD test sebagai evaluasi independen R20 bila frame/sesi serupa masuk training R20.

**Audit tambahan sebelum training:** real positive PRESS di dataset 5G mungkin berbentuk L-sign statis tetapi tidak menyerupai gerakan jempol ketika user bermain. Perlu audit pose dan contoh webcam asli. Jangan memberi label positif dari `point_left/right` berdasarkan orientasi horizontal saja, atau dari `Horiz_H*` HANDS RGB-D berdasarkan nama kelasnya.

### Data collection kecil agar jadwal besok masuk akal

Jika dapat dilakukan **sebelum training siang**, rekam beberapa rangkaian pendek di siang/ruang normal: setiap tangan kanan/kiri, arah kanan/kiri/atas/diagonal, READY tanpa jempol, PRESS dengan jempol, 3–5 siklus buka-tutup jempol, punggung tangan menghadap kamera, pinch/peace/thumbs-up/palm/pen sebagai hard-negative. Ini **saran minimum prototipe**, bukan kebutuhan jumlah sampel yang telah terbukti memadai.

Untuk malam, rekam **uji terpisah** pada lampu kamar atas, low-light tanpa lampu depan, backlight layar/jendela, gerakan dekat/jauh, background ramai, dan jika relevan lampu LED warna. Label event yang benar dengan tombol manual/truth annotation. **Jangan melatih model pada sesi malam sebelum skor locked night-test selesai dan dilaporkan.** Setelah benchmark, footage yang pengguna izinkan bisa menjadi bahan R20 lanjutan dengan test malam baru.

## 4. Arsitektur R20 yang dipertahankan

```text
Browser webcam RAW <video> (pratinjau normal, tidak dimodifikasi)
          |
          +--> Frame preparation CPU: RAW / CLAHE 320 / adaptive candidate
                   |
                   +--> ONE MediaPipe HandLandmarker VIDEO, delegate CPU
                             |                         \
                             |                          +--> hand presence / owner lock / loss
                             v
                         21 landmarks
                             |
                      82-dim feature tracker (R19 parity; R20 changes versioned)
                             |
                       Compact classifier R20 CPU
                             |
              Geometry safety guards + PistolVirtualKeyFSM
                             |
                 READY / PRESS / OTHER / KEYUP / RELEASE_ALL
                             |
                  ONLY NUI LAB diagnostics & Canvas tests

GPU SERVER (OFFLINE): curation -> landmark extraction -> training -> calibration
                  -> model card -> R20 CPU weights -> deployable browser package
```

Catatan: bila frame enhancement menurunkan deteksi pada tangan kecil atau memperbesar noise, jangan pakai default. Worker hanya memisahkan main-thread blocking dan harus mempertahankan timestamp, handedness, koordinat, aspek, ownership, dan peristiwa ke keyboard FSM. **Satu frame in-flight maksimal; frame tertinggal dibuang; tidak ada queue menumpuk.** Saat hasil terlambat, event usang harus dibuang atau `RELEASE_ALL` sesuai lifecycle. Tanpa hand output → bukan PRESS.

**Bekukan baseline C0 R19** model+source+threshold+manifest/checksum. Reproduce di server baru dulu sebelum melakukan training, karena skrip R19 memuat **path absolut `/srv/.../r19-sandbox` dan impor `r18-ux0-sandbox`**. Refactor path menjadi parameter/config R20 secara terisolasi; jangan mengubah file R19 yang sudah dipublikasikan.

### Kohort kandidat wajib

| Kandidat | Training | Faktor pembeda | Tujuan |
|---|---|---|---|
| **C0 R19 frozen** | **Tidak retrain** | Referensi G4 Hybrid sama | Paired comparison wajib |
| **C1 R20-balanced** | **Retrain** 3 dataset R19 yang sah | Sampling/weight per source-class, positive-balanced loss, LR + MLP kecil; original nonaug test | Ukur dampak mengatasi imbalance tanpa data baru |
| **C2 R20-positive-light** | **Retrain** + positive TRAIN HandGesture-5G dengan varian gamma, exposure, noise, blur, CLAHE, dorsal, skala, dan bila tersedia Owner daytime consent | Re-extract 21 landmarks dari *gambar hasil augment*, bukan hanya menambah noise ke 82 fitur | Meningkatkan class READY/PRESS ketika detector masih mengeluarkan landmark |
| **C3 R20-hard-negative** | **Retrain** C2 + negatives tersaring dari bxr7/HANDS dengan relabel serta duplicate/session guard | Pisahkan positive false-accept vs ambiguous; negative mining dengan anotasi manual | Menurunkan false PRESS, erase dan hand ownership tanpa merusak recall |
| **C4 R20-full** | **Retrain** kandidat terbaik dari C2/C3 + curriculum lighting/domain balancing + calibration & temporal thresholds VAL | Kombinasi terukur, hanya jika C2/C3 berguna | Kandidat browser untuk malam |

Gunakan C1–C4 sebagai **eksperimen terpisah** dengan training logs dan bobot distinct. Jika dataset P1 belum berlabel secara sah siang hari, **jangan menunda seluruh training**. Jalankan C0–C2 lebih dulu, tandai C3/C4 blocked/partial secara jujur. C4 tidak boleh diam-diam melatih pada TEST.

**Sweep awal (parameter prototipe, ubah berdasarkan VAL):** model `82→48→24→3`, `82→64→32→3`, `82→96→48→3`; 3 seeds; penimbang kelas capped + per-source sampling; no-augment vs moderate vs strong-aug; class-aware hard negatives; temperature/threshold dan EMA/FSM disetel di VAL, **bukan locked TEST**. Coba logistic regression sebagai ukuran/safety comparator. Bias augment yang menghancurkan pose jempol, memirror label arah tanpa koreksi handedness, atau memotong ujung jari harus dikeluarkan.

**Implementasi training:** gunakan PyTorch/CUDA untuk teacher visual, student distillation dan sweep bila berguna. Catat `torch.cuda.get_device_name`, CUDA, GPU memory, commit, dependency lock, durasi, peak VRAM, energy optional. MLP mini boleh lebih cepat di CPU daripada GPU; jangan menyamakan **server GPU tersedia** dengan **model yang dilatih pasti lebih baik**. Ekspor bobot ke JSON/f32 yang sama dengan runtime TS; uji parity 150+ contoh VAL+TEST hingga **0 argmax mismatch**, error numerik dinyatakan dan diverifikasi. `model.json` yang dipilih harus <=200.000 B raw atau beri penjelasan budget bila berbeda.

**Validation design:** split by person when person metadata available, otherwise scene/session/camera/day/dHash group; video frames dari sesi yang sama tidak boleh tersebar train/val/test; separate lamp-condition slices. `TRAIN` saja untuk normalization, augmentation, oversampling, pseudo-label, tuning feature. `VAL` untuk model/threshold. `TEST` dibekukan, baru dinilai setelah pilihan kandidat selesai. Evaluasi confidence/calibration dan model state pada sequence, bukan hanya per-frame.

## 6. Low-light stack untuk detektor (tanpa melatih ulang MediaPipe)

**Matriks paired per-frame, diutamakan sama input webcam/klip:**

- `L0`: RAW pada resolusi/setting NUI sekarang.
- `L1`: `CLAHE 320` existing (`frame-source.ts`, `clahe.ts`), mode `on`.
- `L2`: `RAW 320` existing, untuk mengisolasi efek downscale dari enhancement.
- `L3`: kandidat RAW 480 / CLAHE 480 hanya bila CPU+latensi masih memenuhi budget.
- `L4`: kandidat luma-aware mild gamma/denoise/CLAHE adaptif. **Tidak langsung menjadi default; bandingkan noise dan detail ujung jari**.

Nilai `DARK_LUMA = 0.28`, `BACKLIGHT_CENTER_MAX = 0.36`, `BACKLIGHT_LUMA_GAP = 0.18`, `ENHANCE_WIDTH = 320` merupakan heuristik **belum terkalibrasi pada webcam pengguna**. Kalibrasikan dengan data TRAIN/VAL atau eksperimen webcam awal, bukan memilih parameter dari night locked test lalu mengklaim independen.

**Tiga outcome terpisah:**
1. **Hand detector:** fraction hand-visible frames with valid landmarks, missed frames/dropouts, false hand, reacquisition delay, by lighting, hand size, distance.
2. **Classifier** **hanya pada frame dengan landmark valid:** `PRESS`/`READY` P/R/F1, false PRESS vs classes, `OTHER` precision, left-hand/dorsal slices, calibration.
3. **E2E controller:** unintended `KEYDOWN`/minute, stuck keys, release latency, jump count, RIGHT→RIGHT+JUMP→RIGHT continuity, ownership false switch.

Menilai classifier hanya pada frame terdeteksi bisa menyembunyikan kegagalan e2e di gelap. Laporkan **recall denominator seluruh frame valid ground-truth** dan **conditional classifier accuracy given detected** secara terpisah. `NO_HAND` adalah tracker state, bukan kelas dilatih pada MLP.

## 7. CPU-only browser runtime dan budget 25 MB

### Implementasi runtime yang perlu diuji pada R20 sandbox

1. **Force all NUI inference delegates to CPU**. `src/camera/hand-landmarker.ts` `createHandLandmarker` saat ini GPU-first; buat mode CPU-only yang eksplisit di kandidat/feature flag **hanya NUI Lab**, bukan otomatis memodifikasi semua route gameplay. `face-anchor.ts` sudah CPU, audit pembuat landmarker lain bila route terkait memanggilnya.
2. Jalankan kandidat **MediaPipe HandLandmarker CPU di Web Worker** memakai `ImageBitmap` (transferable) dengan contoh Google `mediapipe-samples-web/.../workers/hand-landmarker.worker.ts`. Pertahankan mode `VIDEO`, monoton timestamp, satu inflight, latest-frame-wins, disposal `bitmap.close()`, abort saat tab hidden, stop/route change, restart model/worker crash dan `RELEASE_ALL`. Worker harus diuji pada Brave/Chromium target dan deployment static export (`next build`), bukan diasumsikan kompatibel.
3. Bandingkan setidaknya **A: CPU main-thread lama** vs **B: CPU worker** pada video/mesin sama. Sematkan pemantauan CPU total, worker, UI FPS, detectHz, p50/p95 e2e action, long tasks, battery if available. Worker bukan jaminan inference FPS lebih tinggi.
4. Uji `numHands=2` untuk fungsi distraksi/owner-lock seperti existing, baru ablation `numHands=1` bila stabilitas ownership tidak berkurang. Jangan diam-diam mengubah ke satu tangan karena bisa mengabaikan tangan pengganggu dan memilih salah.
5. Face detector tidak boleh terus-menerus menurunkan hand update; bandingkan scheduler baseline dan candidate hand-priority, tanpa merusak perlindungan false owner. Raw preview tetap video tanpa brighten/smoothing shader; preview latency vs detector separately.

### Protokol pengukuran jaringan (strict)

- Definisikan `B-USER` sebagai **jumlah byte yang ditransfer browser untuk journey pertama yang dibutuhkan siswa**, termasuk WASM loader, `.wasm`, `.task`, MLP R20, face detector, JS/CSS, font/aset yang dimuat. Ukur dua perjalanan terpisah: **NUI Lab webcam test** dan **student onboarding → canvas → level gameplay**. Jangan menggabungkan semua rute yang tidak diperlukan ke satu kunjungan, tetapi jangan menghilangkan dependency yang benar-benar terunduh.
- Chromium CDP `Network.loadingFinished.encodedDataLength` dengan `Network.requestWillBeSent`/`responseReceived`, profil bersih, cache dinonaktifkan, Service Worker disabled/unregistered, single browser process. Simpan HAR/report request-by-request, group unique/repeat, cold/warm cache, compression headers, 2 refresh dan total cost.
- **Hard limit:** `B-USER < 25.000.000 B` pada masing-masing journey cold. Baseline R19 **11.356.084 B** berasal dari simulated harness yang bukan pengukuran final deployed `main`, jadi catat sebagai pembanding historis saja.
- Audit total model `hand_landmarker.task` (~7,82 MB pada R19), WASM (~2,72 MB), BlazeFace, dan R20 MLP wire; hindari duplicate downloads, tidak mengunduh dataset atau `.y4m` ke laptop siswa.
- Model size <=200.000 B raw dan device RAM/JS heap: ukur, **jangan memberi angka target RAM tanpa pengukuran baseline**. Pilih ambang RAM setelah real benchmark. Offline caching boleh, tetapi tidak boleh dipakai untuk menyembunyikan cold cost.

### Gate performa **prototipe**, bukan klaim jaminan

| Gate | Target R20 uji fisik | Cara memutuskan |
|---|---|---|
| Unduhan | **<25.000.000 B cold B-USER** | **Hard fail** jika >= batas pada journey yang diwajibkan |
| Delegate ML | **CPU** hand+face+gesture, no GPU inference | Browser metrics, instrumentation delegate, source review; flag GPU inference = fail |
| Model classifier | **<=200.000 B raw** | File stat/export/sha256; bila lebih, kandidat tidak dipilih tanpa justifikasi |
| CPU hand detections | **Target >=20 Hz** pada laptop target; floor sementara 15 Hz untuk diagnosis | Target R&D agresif, R19 browser headless sebelumnya 14,18 FPS. Jika tidak tercapai, laporkan sebagai blocker tanpa memoles status |
| UI FPS | **Target >=30 FPS** saat deteksi aktif | Measurement p5/p50 FPS selama 3 min; worker/main-thread comparison |
| Event latency | **Target p95 <=150 ms** dari physical intent hingga key event | Berbasis rekaman timestamp/truth; jika ground truth input tidak bertimestamp, nyatakan estimasi bukan hasil event-to-key |
| No stuck key | **0** pada stop/hidden/no-hand/reacquire sepanjang skenario | Fail on any stuck state |
| Anti-distraksi | False PRESS, Erase, lock switch **tidak lebih buruk dari C0** pada paired test yang sama | Catat per menit, support, confidence bounds; zero pada limited set bukan pembuktian universal |
| Low-light | Detection recall / successful controller events **harus membaik atas baseline paired CPU R19** di slice target tanpa safety regression | Delta absolut+confidence intervals; aspirasi awal >=10 percentage points bila data memadai, **bukan klaim sebelum diuji** |
| Long tasks | Penurunan signifikan dari CPU main-thread; no detector call on UI thread pada worker variant | CDP PerformanceObserver; residual other long tasks dilaporkan |

## 12. REVISI ARSITEKTUR: Teacher GPU → Distilled Student CPU (solusi utama)

**Tegaskan pemisahan:** model berat **BOLEH** dijalankan penuh saat training di GPU server. Output deployment **BUKAN** teacher / MobileNet besar, **BUKAN** seluruh pipeline PyTorch atau Keras, dan **BUKAN** checkpoint `.pt`. Output akhir adalah bobot student terverifikasi yang dibaca oleh runtime CPU browser. Membuat `.tflite` dari MobileNet besar saja tidak menjamin latensi CPU kecil; quantization mengurangi ukuran dan *kadang* mempercepat tetapi harus diukur pada perangkat target.

### 12.1 Dua jalur pembelajaran yang kompatibel dengan input runtime

| Komponen | Saat training di GPU | Saat runtime CPU user | Catatan kejujuran |
|---|---|---|---|
| **Image teacher T-IMG** | Model pretrained MobileNetV3/EfficientNet-lite *kandidat* (atau backbone lain dengan lisensi jelas) pada crop RGB bertanda pose dan lighting; fine-tune + class-balanced losses | **Tidak diunduh dan tidak dipakai** | Teacher lihat RGB, student landmark tidak. Hanya contoh dengan landmark valid yang bisa distil langsung |
| **Temporal teacher T-TEMP** | Encoder temporal (1D TCN/GRU/transformer kecil) pada *sequence* landmark plus hasil RGB teacher; supervised transisi `READY → PRESS → RELEASE` | **Tidak diunduh** | Tidak boleh menciptakan label transisi dari gambar statis berulang |
| **Student S-SPATIAL** | MLP ringan 82→64→32→3 atau 82→96→48→3 dengan CE/focal class-aware + KL distillation dari teacher; sekaligus embedding feature kualitas landmark | **Pure TS Float32** sebagai baseline cepat | Hanya berjalan jika HandLandmarker menghasilkan landmark |
| **Student S-TEMP** | Student kecil causal TCN / depthwise-1D atas **history** 4–8 frame valid dan mask/missingness; distil dari T-TEMP | **CPU JS/WASM**, jika benar-benar lebih bagus daripada S-SPATIAL | Tidak boleh memakai future context atau menambah delay gerak terlalu besar |
| **G4 geometry + FSM** | Training-free baseline, VAL tuning terbatas, adversarial tests | **Tetap di CPU** | Berfungsi sebagai safety gate, bukan disingkirkan demi probabilitas tinggi |
| **CPU low-light front-end** | Pilih/kalibrasi pengolahan dengan data train/val dan real video | RAW → adaptive photometric enhancement → MediaPipe CPU | Menangani dropout di luar kemampuan student berbasis landmark |

### 12.2 Distillation loss yang harus diuji, bukan diasumsikan bekerja

Pada sampel `i` dengan ground truth valid dan **landmark tersedia**, bandingkan:

`L = λ_CE * CE(y_i, p_student) + λ_KD * T² * KL(softmax(logits_teacher/T) || softmax(logits_student/T)) + λ_T * L_temporal + λ_C * L_consistency`

- Parameter awal eksperimen: `T={2,4}`, `λ_KD={0,0.25,0.5}`, `λ_CE=1` (hipotesis, bukan nilai optimal); `λ_T, λ_C` hanya bila *temporal ground truth* benar-benar tersedia.
- **C6 supervised student tanpa teacher** wajib sebagai kontrol. **C7 teacher–student distilled** pada split/input sama, architecture sama, seed sama. Jika teacher justru menurunkan performa low-light/false action, buang distillation dan pilih C6.
- Teacher RGB dapat memberi soft-target untuk crop positif/negatif **hanya setelah label diaudit**. Jangan mengganti label resmi dengan pseudo-label tanpa confidence dan *human review*. Pseudo-label tidak boleh mencemari validation/test.
- Untuk subjek/sesi yang hanya punya RGB, jalankan MediaPipe extraction *offline* dalam mode sama. Jika landmark gagal, **catat failure detector**, bukan melatih MLP dengan feature `0` palsu seolah pose OTHER.
- Kelas tetap `POINT_READY`, `POINT_PRESS`, `OTHER`; `POINT_RELEASE` adalah **transisi temporal/event**, `NO_HAND` adalah **status tracker**. Jangan membuat kelas keempat/kelima tanpa bukti dan izin lingkup.
- Class counts R19: READY 302, PRESS 196, OTHER 16.588 train. **Oversampling frame yang sama bukan tambahan informasi independen**. Prioritaskan keragaman subjek, tangan kiri/kanan, dorsal, lampu atas, punggung tangan ke kamera, jempol partially folded, dan sesi baru.

### 12.3 Dataset training teacher dan student secara tepat

1. **HandGesture-5G** sudah punya L-sign dan Pointing Up, cocok untuk *positive visual teacher* dan student. Augmentasikan low exposure, shot/read noise, color cast, white balance, motion blur, kompresi, punggung tangan, perspektif **hanya bila label dan geometri tetap benar**. Utamakan gambar asli berlabel daripada duplications.
2. **Natural RGB v3** berisi variasi pencahayaan dan kelas negatif. Teacher belajar hard-negative, tetapi jangan menjadikan `point_left/right` PRESS tanpa melihat jempol. Subject/session disjoint.
3. **IPN HandS** memberi sequence asli OTHER untuk temporal negative/anti-distraksi. P1F/C1F/2C1 tetap quarantine untuk PRESS; R19 membuktikan conflation berbahaya.
4. **Egocentric/Exocentric Hands v2** dan **HANDS RGB-D** merupakan dataset *unlabeled/label-mismatch* untuk pistol: gunakan untuk teacherenhancement/stress eval; hanya ambil train hard-negative yang telah direlabel dan tidak berasal dari locked OOD test yang sama. HANDS `Horiz_H*` = lima jari, BUKAN pistol, `One_V*` = READY-like.
5. **Exocentric Hand Interaction v2** `2.48 GiB` bukan prioritas siang pertama. Streaming bagian yang relevan, audit lisensi/frame/scene dan sampling jika ada disk/CPU/GPU budget; tidak masuk training tanpa label yang benar.
6. **Owner webcam consented daytime data** adalah sumber paling berharga untuk *domain adaptation* jika tersedia sebelum training: beberapa sesi nyata berisi READY/PRESS/RELEASE + hard-negative. Pisahkan per session, **reserve malam sebagai held-out real-world test** sehingga hasil malam bukan self-fulfilling leakage.
7. **DimHand, LLHands/XPose, MGR-Dark** tetap BLOCKED; jangan mengklaim sudah digunakan. HaGRIDv2 tidak diadopsi untuk weights produk sebelum review lisensi terpisah.

### 12.4 Bobot student: pilih format yang menghemat tanpa menambah runtime besar

Bandingkan dalam browser **pada dataset dan perangkat sama**:

- `S0 FP32`: ekspor bobot **compact binary Float32Array** plus small metadata & checksum; bandingkan ukuran dengan JSON R19 `122,768 B`. *Binary f32 bukan automatically 4x smaller* dari memori floats, tetapi sering jauh lebih padat dari decimal JSON.
- `S1 INT8 weights`: per-channel weights + scales, input float32/activation float32 atau quantized; implement kernel yang benar serta parity, **uji latency total**, bukan hanya ukuran. Dequant per inference bisa lebih lambat untuk MLP sangat kecil.
- `S2 TFLite INT8`: hanya jika memanfaatkan runtime MediaPipe/WASM **yang sudah tersedia** tanpa menyebabkan WASM kedua yang menduplikasi biaya. Jika butuh LiteRT/TFLite baru yang lebih besar dari bobot student, tetap gunakan pure TS.
- `S3 QAT`: hanya bila INT8 PTQ menurunkan recall PRESS/false action; training-aware quantization memerlukan representative low-light samples dan validasi terpisah.

**Pilih berdasarkan E2E CPU p95 + transfer bytes + recall dan false PRESS**, bukan label `.tflite` atau klaim “INT8 pasti cepat”. Jika model R20 sedikit lebih besar tetapi masih total <25 MB dan inference JS cepat, jangan mengejar quantization yang merusak keselamatan.

## 13. SOLUSI LOW-LIGHT DI CPU: detector dulu, student kemudian

**Kegagalan dibagi tiga dan masing-masing punya tindakan berbeda:**

| Kegagalan | Gejala | Solusi R20 yang benar | Solusi yang tidak cukup |
|---|---|---|---|
| `DETECTOR_MISS` | MediaPipe output 0 hands walau tangan terlihat di video | Adaptive RAW/CLAHE/gamma, camera exposure constraints feasibility, brightness routing, reacquisition, ROI/resizing benchmark CPU | Retrain landmark-only MLP saja |
| `LANDMARK_JITTER_OR_BAD_POSE` | Landmark muncul, tetapi jempol/finger coordinates melompat atau salah | Temporal student + validity/missingness mask, confidence guard, smoothing pada *landmark/visual pointer* yang tepat dan hysteresis FSM | Lebih banyak sample OTHER saja |
| `FALSE_HAND_OR_DISTRACTOR` | Orang lain/objek mengambil hand lock atau salah PRESS | Multi-hand identity/ownership guard, negative mining relabel, track continuity, no-auto-steal, PRESS veto + REARM | Memaksa numHands=1 tanpa uji ownership |

### 13.1 CPU photometric candidate cascade, bukan CLAHE permanen

**Mode A0** native RAW pada input video terukur; **A1** RAW scaled 320 (isolasi resize), **A2** CLAHE 320 existing, **A3** luma LUT / mild gamma + noise-floor clamp / denoise ringan + CLAHE opsional, **A4** adaptive selection: pengolahan aktif hanya ketika prediksi manfaat cukup kuat berdasar central luma, frame quality dan history. Jika hasil A4 lebih buruk daripada A2, pilih A2. Semua pada CPU Canvas2D/TypedArray dan hanya pada frame deteksi, *preview video tetap natural*. Tidak mengirim frame ke server.

**Penting**: CLAHE di kondisi *nyaris hitam* dapat **memperbesar noise dan false detections**. Penelitian 2026 tentang enhancement adaptif untuk object recognition menemukan kondisi sangat gelap dapat menjadi lebih buruk dengan CLAHE/gamma tertentu. Jadi harus paired benchmark, bukan “CLAHE on selalu”. Sumber teknis: https://www.mdpi.com/2076-3417/16/15/7635

**Mode fallback ketika tangan tidak terdeteksi:** satu frame enhanced adaptif pada deteksi berikutnya, bukan full-resolution enhancer berat di setiap frame. Kegagalan berturut-turut menurunkan sementara cadence sesuai CPU budget, bukan menumpuk queue. Detektor tidak boleh melakukan inferensi RAW dan CLAHE untuk setiap frame secara berurutan bila total CPU melebihi budget.

### 13.2 Hand tracking / owner lock / safety saat missing landmarks

- MediaPipe `VIDEO` melakukan tracking dari ROI sebelumnya untuk mengurangi palm detection; threshold `minHandPresenceConfidence` dan `minTrackingConfidence` memengaruhi kapan re-detect. Uji parameter di VAL dan webcam, jangan sekaligus dengan model baru. Dokumen resmi: https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker
- **Bila satu frame tanpa landmark:** jangan membuat `POINT_PRESS` palsu; FSM safety memutus/menahan sesuai kontrak R19, `RELEASE_ALL` untuk missing/timeout. Tracking-prediction untuk **visual overlay boleh** dibedakan dari sumber input; overlay yang halus tidak boleh berarti tombol yang tidak valid.
- **Satu tangan aktif** dengan ID per acquisition. Tangan lain boleh dideteksi sebagai distractor tetapi jangan merebut lock otomatis. Saat crossing, blur, occlusion, atau wajah orang lain lewat, release dan re-arm sesuai aturan.
- Uji *raw vs smoothed* dan R17 `PointSmoother` yang masih dipakai untuk tinta. Smooth cursor **tidak bisa** menggantikan confidence validasi gesture. Catat penurunan jitter sekaligus delay tekan/lepas.

### 13.3 Opsional **Tiny-ROI fallback** jika baseline detector tetap gagal

TIDAK otomatis dibangun pada hari pertama. Jika di malam hari kondisi tertentu menunjukkan `DETECTOR_MISS` berulang walaupun A0–A4 sudah optimal, lakukan R20-PHASE-2 yang eksplisit:

1. Gunakan GPU server untuk melatih teacher hand ROI/keypoint proposal pada pasangan RGB rendah-cahaya + gambar terang **dengan GT/label valid**.
2. Distil *tiny image-to-ROI* student INT8 untuk **reacquisition saja** di CPU browser ketika MediaPipe kehilangan ROI; bukan pengganti MediaPipe landmark model, dan bukan teacher yang ikut diunduh.
3. Tunggu bukti bahwa MediaPipe Task dapat mengonsumsi ROI/proposal eksternal secara aman. Jika API tidak mendukung ROI injection, **jangan mengarang integrasi internal**; alternatif adalah model standalone yang menciptakan landmarks dengan validasi ketat, tetapi itu memperluas scope dan harus diaudit terpisah.
4. Bandingkan extra model bytes, CPU utilization, false hand, dan recovery coverage. **NO-GO** bila menambah model membuat total download >25MB, latency naik, atau false press lebih buruk.

Solusi defensif ini mengakui keterbatasan fundamental: *teacher RGB tidak bisa menciptakan landmark yang hilang pada runtime student landmark-only*.

## 14. KONTRAK RUNTIME CPU-ONLY: Worker dan budget yang benar-benar diukur

### 14.1 Perubahan source yang dibutuhkan pada cabang eksperimen

- Existing `main@8969502` `src/camera/hand-landmarker.ts` default **GPU-first**, sedangkan `face-anchor.ts` sudah CPU. R20 candidate harus memaksa `baseOptions.delegate='CPU'` untuk jalur NUI, disertai diagnosa aktual yang membuktikan tidak ada GPU inference di inisialisasi dan setelah recovery. Jangan kirim seluruh frame pixel kembali ke main.

| UI responsiveness | **≥30 FPS** target UI dan zero *detector-caused* main-thread >50ms longtasks setelah worker | Performance trace real browser, no fallback sync detect on main |
| Gesture latency | **p95 ≤150ms** press→event sebagai stretch target untuk user testing | Physical video truth marks / perf timestamps, jangan disimpulkan dari classifier inference |
| Controller safety | **0 stuck keys** setelah hand lost/stop; false press target <= R19 pada paired night/negative suites | Time stamped events + owner ground truth |
| Low-light improvement | Positif vs frozen R19 pada paired scenes tanpa peningkatan false PRESS | Total GT hand coverage dan conditional classifier recall terpisah |

**Jika ≥20Hz tak tercapai, jangan diam-diam mengubah kalimat menjadi PASS.** Tunjukkan tradeoff real CPU dan gate yang tidak lulus. Worker memulihkan respons UI tetapi **tidak otomatis menambah throughput detektor**.

## 16. Failure taxonomy dan skenario evaluasi lengkap

**Telemetry wajib satu row per sampled frame/trigger**: timestamp camera capture, input size, preprocess chosen/ms, mean/center luma, hand count, detection result, hand detection/presence/track params, landmark valid/quality, handedness, owner lock ID, 82-feature norm, logits/3 probs, geometry veto reason, FSM event, left/right/jump, per-stage latencies, missing-frame count, CPU delegate, dropped frame. **DILARANG** mengklaim absolute action-latency bila trigger fisik manusia tidak punya GT timestamp.

- **Low light / optical:** overhead room light, dim monitor-only, backlight center silhouette, bright-to-dark transition, colored light red/green, highlights/glare, overexposure, noisy camera, glasses/reflection objects, hand small/far, compression artifacts.
- **Pose/geometry:** left/right hand, dorsal/palmar, right-hand pointing left across chest, thumb half-open, short press, long hold, downward neutral, diagonal LEFT/RIGHT+JUMP, mirror preview and true camera orientation.
- **Distractors:** second person crossing, another hand closer/larger than owner, person walking behind, printed image/hand poster, pen/fan/stick, fist/peace/thumbs-up/open palm/pinch/near pinch, occlusion, moving foreground objects.
- **Safety:** camera stop/tab hidden/worker crash/hand leaves frame/landmarks lost and back/rearm, no stuck key, no bystander PRESS, no false erase, no ghost events after route switch.

**Report confusion by lighting AND stage**: `GT hand visible -> detector coverage -> landmark quality -> conditional READY/PRESS accuracy -> e2e active-event recall`; false-action **per minute** and over-count vs physical intended events. Night test is *real-world held-out* on current model; if used for tuning, call it DEV set and collect a **new independent** night session for final confirmation.

## 17. Why this is NOT simply convert big model to TensorFlow/Keras

1. Training model on GPU is not the same as running it on CPU cheaply. Image CNN large can still require heavy multiply-add even when `.tflite` is compressed. **Train teacher large offline, distil student tiny online.**
2. Google AI Edge confirms INT8/PTQ generally reduces size and can improve CPU runtime, but **small networks and actual kernels vary**. For existing small MLP, Float32 TS may be faster and avoids adding another WASM runtime: https://developers.google.com/edge/litert/conversion/tensorflow/quantization/post_training_quantization
3. Google Hand Landmarker task contains **both palm detector and hand landmark model**. It is the heavy component in R19 (~67ms/frame on their headless CPU), and cannot be made faster by compressing the 122KB MLP alone: https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker
4. Google officially notes synchronous video inference blocks calling thread and recommends Web Worker on web. Worker shifts blocking away from UI; **does not reduce raw detector FLOPs**: https://developers.google.com/edge/mediapipe/solutions/tasks
5. No real low-light signal means no algorithm can conjure a reliable hand pose. Design a **graceful degradation** mode, keep virtual keys fail-closed and show actionable lighting guidance rather than inventing confidence. This is a safety/UX limitation, not a failure of GPU training.

**Operational verdict:** target R20 tetap training besar di GPU, satu student ringan di CPU, MediaPipe CPU di worker, low-light CPU preprocessing, no-GPU inference dan network <25 MB. Jika data atau hardware tidak mendukung semua angka, laporkan secara kuantitatif dan jangan menyebutnya completed.
